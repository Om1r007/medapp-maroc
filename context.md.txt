🎯 Brique 9a — Création du site vitrine medapp.ma
Vision
Créer un nouveau projet Next.js dans le monorepo apps/web-landing/ qui sera le site vitrine de Medapp Maroc. Ce site est uniquement marketing/conversion : il transforme un visiteur en utilisateur de l'app patient.
Inspiration directe : Medadom (medadom.com) + Forward Health (forwardhealthtech.com).
⚠️ Règles d'or NON NÉGOCIABLES

Ce projet n'a AUCUN code produit — pas d'auth, pas de dashboard, pas de queue. Juste des pages statiques marketing.
Tous les CTA pointent vers app.medapp.ma (variable d'environnement NEXT_PUBLIC_PATIENT_APP_URL).
Lien "Espace médecin" pointe vers pro.medapp.ma (variable NEXT_PUBLIC_DOCTOR_APP_URL).
Design system Forward-style identique à celui des apps (Brique 7) — palette, typo, composants.
Mobile-first strict — le site doit être impeccable à 375px.
SEO-ready — métadonnées, Open Graph, schema.org structured data, sitemap.
Performance maximale — Lighthouse > 95 sur Performance, Accessibility, Best Practices, SEO.
Pas de tracking pour le MVP — Google Analytics et Hotjar viendront plus tard.

🏗️ Setup technique
Création du projet
Dans le monorepo, à la racine :
bashmkdir apps/web-landing
cd apps/web-landing
# Créer un nouveau Next.js 15 avec TypeScript + Tailwind
Configuration package.json :
json{
  "name": "web-landing",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "dev": "next dev -p 3002",
    "build": "next build",
    "start": "next start -p 3002",
    "lint": "next lint"
  }
}
Port 3002 (3000 = patient, 3001 = médecin, 3002 = landing).
Variables d'environnement (.env.local)
envNEXT_PUBLIC_PATIENT_APP_URL=http://localhost:3000
NEXT_PUBLIC_DOCTOR_APP_URL=http://localhost:3001
NEXT_PUBLIC_SITE_URL=http://localhost:3002
Et .env.example correspondant pour la prod :
envNEXT_PUBLIC_PATIENT_APP_URL=https://app.medapp.ma
NEXT_PUBLIC_DOCTOR_APP_URL=https://pro.medapp.ma
NEXT_PUBLIC_SITE_URL=https://medapp.ma
Design system partagé
Copie exactement le tailwind.config.ts de web-patient (palette Forward, typo Plus Jakarta Sans, fontSize, borderRadius, boxShadow). Pas de divergence.
Recopie aussi les composants UI nécessaires depuis web-patient/components/ui/ :

Button, Card, Badge (au minimum)

⚠️ Pour MVP, dupliquer est acceptable. En V2 on factorisera dans packages/ui.
Update Turbo
Met à jour turbo.json à la racine pour inclure le nouveau projet dans les pipelines dev, build, lint.

⚠️ Points d'attention CRITIQUES
1. Ne pas mentir sur les chiffres
Pour le MVP, tu n'as pas de vrais médecins ni de vraies consultations. Ne pas inventer "+12 000 consultations" si c'est faux. Préfère :

"Bientôt disponible · Soyez parmi les premiers patients"
"Recrutement actif · Plus de 50 médecins en cours d'inscription"
Sois honnête sur le statut beta. Ça te protège légalement et c'est plus crédible.

2. Ne pas inventer de témoignages
Aucun fake testimonial. Section "Bientôt vos témoignages" en attendant les vrais.
3. Pages légales : placeholder mais pas absentes
Les pages mentions/confidentialité/CGU doivent exister avec un placeholder explicite. Sinon, ton site est non conforme dès le jour 1.
Avant prod, fais valider par un avocat marocain spécialisé en droit du numérique. Compte 5000-10 000 MAD pour un pack complet.
4. Cookies CNDP
Pour la prod, bandeau cookies obligatoire (loi 09-08). Pour MVP en local, pas urgent. Mais avant la prod, ajouter un bandeau (utilise cookie-banner-react ou similaire).
5. Contact email = configure-le bien
Pour le form contact, dès que tu déploies, configure :

Soit Postmark (essai gratuit, très bon pour les transactionnels)
Soit Mailgun (free tier généreux)
Soit SES (AWS) si tu veux scaler

Email de réception : contact@medapp.ma (à créer chez ton hébergeur DNS).
